Negative Inventory Control

Configurable Allow / Warn / Approval Required / Block policies for negative stock, with a full audit trail and an approval workflow — for Odoo 19.

Version 19.0.2.1.0   ·   License LGPL-3   ·   Depends on stock, mail   ·   Core files modified 0

Why this exists

Odoo lets stock go negative — silently, always, everywhere

Deliveries, internal transfers, scrap, manufacturing consumption, and inventory adjustments can all push on-hand quantity below zero with no warning, no block, and no record that it happened. That's deliberate in core Odoo, not a bug — which means the business gets no say in the matter unless something is built for it. This module is that something.

The policies

Four policies, and exactly what each one does on screen

Set a policy at Company, Location, Product Category, or Product level — leave any of them blank to inherit from the next level up. Whichever setting is strictest always wins, regardless of which level it came from, so a deliberately-tightened guardrail can never be silently overridden by a looser one elsewhere.

ALLOW

Unchanged Odoo behaviour. The default — installing this module changes nothing until you configure it.

On screenNothing. Still recorded in the audit log.

WARN

Proceeds, but you're told about it — not left to notice it later.

On screenAn on-screen notification at validation, plus a chatter note.

APPROVAL REQUIRED

Pauses before anything is written. A Stock Manager must approve it, with a reason on record.

On screenA request form opens; the transfer resumes automatically once approved.

BLOCK

Refused outright. Nothing is written to stock.

On screenAn error explaining exactly what would have gone negative.

Product → Category → Location → Company   —   strictest setting always wins

Approval workflow, conceptually

Pause, review, resume — automatically

1. Detected  —  Before anything is written to stock.

2. Paused  —  A request is created with the exact product / location / quantity.

3. Reason submitted  —  The requester explains why it should be allowed.

4. Reviewed  —  A Stock Manager approves or rejects it.

5. Resumed  —  On approval, the original transaction completes on its own.

Covers every path that can independently drive stock negative: picking-driven transfers (deliveries, internal transfers, manufacturing component pickings), scrap, and inventory adjustments — not just deliveries.

Under the hood

Built to hold up, not just to demo

Detects every path, not just deliveries

Deliveries, internal transfers, scrap, unbuild, manufacturing consumption, and inventory adjustments all funnel through the same enforcement layer — nothing slips through a side door.

Zero behaviour change on install

Every policy defaults to Allow / inherit. Installing this module changes nothing on an existing database until you configure it.

Full audit trail, even for Allow

Every negative-stock event is logged — including the ones you chose to allow — so "we permitted this" is always on record, not just the ones that got stopped.

Multi-company aware

Requests and audit-log entries are scoped per company by record rule — a user restricted to one company never sees another's.

Concurrency-safe approvals

Two managers clicking Approve on the same request at the same instant can't both resume the transaction — the row is locked before either one proceeds.

Audit entries survive a Block

A blocked attempt rolls back its own transaction, so that log entry is written on an independent database connection — the record of the attempt survives even though the attempt itself never did.

No core files are modified. Depends only on stock and mail — manufacturing consumption is covered automatically through the shared stock-move mechanism if/when the Manufacturing app is installed, with no hard dependency on it.
